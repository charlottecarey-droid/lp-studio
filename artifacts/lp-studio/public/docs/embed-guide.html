Integration guide

Embedding an LP Studio page on your website

One script tag renders a hosted LP Studio page inside a section of your site — optionally replacing a section you already have, and optionally personalized per visitor by a link parameter. Roughly fifteen minutes of work, most of it verification.

What you get from us

  • The snippet, with your host and page already filled in
  • The link parameter name, if you're using personalized links

What we need from you

  • The CSS selector of the section the embed should replace, if any
  • Our host allowed in your frame-src, if you enforce a CSP

Installing

  1. Paste the snippet where the content should appear

    <div id="lp-page"></div>
<script async src="https://YOUR-HOST/api/embed/page.js"
        data-page="your-page-slug"></script>

    The script renders into the <div> above it. If your CMS separates scripts from markup, put the div where the content belongs and point the script at it with data-target="#your-container" instead.

  2. To replace an existing section, name it

    <script async src="https://YOUR-HOST/api/embed/page.js"
        data-page="your-page-slug"
        data-hide="#the-section-to-replace"></script>

    That section is hidden while our content renders, and restored automatically if the page is ever unpublished — so an expired embed falls back to your own content rather than leaving a gap or an error.

  3. Allow the frame in your CSP

    If your site sends a Content-Security-Policy header, add our host to frame-src. Without it the browser blocks the frame silently and the section simply appears empty — this is the single most common reason a correct snippet shows nothing.

  4. Verify

    Load the page. The content should appear and the container should size itself to fit, with no inner scrollbar. If you used data-hide, your original section should be gone. Check the browser console for CSP or network errors if not.

Personalized links

The same slot can render differently per visitor. Our team sends each recipient a link to your page carrying a token — for example ?lp_agenda=a1b2c3 for an event agenda, or ?lp_page=… for a page embed — and the widget renders that recipient's version. 

<div id="lp-agenda"></div>
<script async src="https://YOUR-HOST/api/embed/agenda.js"
        data-param="lp_agenda"
        data-hide="#your-existing-agenda"></script>

Visitors arriving without a token see whatever you already had — the widget stays out of the way entirely unless we also configure a fallback (a data-default token on agenda embeds; the data-page page on page embeds). A visitor who has used a personalized link once keeps seeing their version on later visits to that page, even without the link.

Naming

The parameter is lp_agenda, not agenda — RainFocus already uses ?agenda on event sites. If a name collides with something on your site, tell us and we'll change it; it's configurable on our end. And if you install more than one embed, each gets its own parameter name (we supply them) — that's what keeps a link meant for one slot from ever affecting another.

Attribute reference

AttributePurpose
data-page Which page to render — and, when personalized links are in play, the fallback everyone without a link sees. Page embeds only.
data-param URL parameter carrying the personalization token. We supply the name; each embed on your site gets its own.
data-default What visitors without a token see. Agenda embeds only — page embeds use data-page as the fallback. Omit to leave your own content in place.
data-hide CSS selector of a section to replace. Restored automatically if the embed has nothing to show.
data-target CSS selector of the container to render into, when it isn't adjacent to the script tag.
data-mode Set to page for a full-page takeover, which keeps full-height heroes at true viewport height. Omit for a section.

What the script does

For anyone reviewing third-party code before it ships:

  • Inserts one <iframe> pointing at our host, and sets its height from a postMessage sent by that frame. Messages are accepted only from the frame it created, and only that one message type.
  • Reads your page's query string, to pick which version to render and to carry campaign parameters into the embedded page.
  • Stores a single token in localStorage on your domain, so a personalized visitor stays personalized on return visits. Nothing else is written, and no cookies are set on your domain.
  • Makes no requests other than to our host, and reads nothing else from your page.

Everything inside the frame is isolated from your site by the browser: our styles cannot affect your page, and our code cannot read it.

If something looks wrong

Nothing renders at all

Usually the CSP frame-src step. Check the console for a blocked-frame error. Otherwise, confirm the host in the snippet matches the one we gave you — the page is looked up against whichever host requested it, so a mismatched host returns nothing even with a valid page name.

The wrong content renders

Check data-page against the value we sent. It's a short name like sdp-slc, not a full URL.

It's much taller than expected, or looks zoomed in

Tell us — that's ours to fix, not yours. It means the embedded page is sizing against the frame rather than your page.

Your original section didn't disappear

The data-hide selector didn't match anything. Confirm it against the live DOM; it must be a valid CSS selector, and IDs are the safest choice since utility classes change when the page is restyled.

It vanished and our old section came back

That's the intended fallback: the page it pointed at is no longer published. Working as designed on your side — ask us to republish.
