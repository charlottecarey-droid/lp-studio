Good question — the URL and screenshot paths have their own specific failure modes that compound the general "bare-bones" issue. I traced through custom-blocks-generate.ts (lines 79–96 for Firecrawl, 877–901 for vision assembly) and brand-import-from-url.ts. Here's what's going wrong and how to fix each one:
1. The markdown is truncated at 8,000 characters. (custom-blocks-generate.ts:96 — .trim().slice(0, 8000).) A real marketing page easily runs 15–25k chars, and the bottom of the page is usually where the best language lives — testimonials, comparison tables, FAQ, CTAs. The model sees the hero and top features, misses the rest, and fills in generic copy for the parts it didn't see. Raise this to 24,000 minimum, or better: don't truncate at all — chunk it.
2. The framing of the reference content is passive to the point of being useless. Current prompt text: "REFERENCE PAGE TEXT (url): ... Use this to ground copy and structure where relevant." That phrase — "where relevant" — gives the model permission to ignore the reference entirely, which is usually what it does. Rewrite to something like: "REFERENCE PAGE — STUDY THIS CAREFULLY. This is the brand's actual marketing language. Mirror the voice, sentence length, specific vocabulary, and information density. Treat their headlines as templates and rewrite them for the user's topic. Every sentence in your output should feel like it could have appeared on this page — never generic marketing copy." That single change moves outputs noticeably toward the reference.
3. The screenshot is passed in with zero instructions on what to use it for. userParts.push({ type: "image_url", image_url: { url: visionImage } }) — that's it. The model sees a picture and is left to infer purpose. Add a paragraph in the user prompt that pairs with the image: "VISUAL REFERENCE: Study the layout, color palette, typography hierarchy, density of information, and visual style of this screenshot. Match the *feel* — is it premium/editorial, scrappy/casual, dense/airy, dark/light? Your generated HTML+CSS should evoke the same aesthetic, not a generic template." Without this, the screenshot is barely doing any work.
4. Firecrawl is set to onlyMainContent: true and waitFor: 1500. (custom-blocks-generate.ts:86.) Two problems with that combination: onlyMainContent strips nav, footer, CTA bars, sticky banners — exactly the elements people most often want to clone. And 1.5s is tight for modern JS-heavy marketing pages that render hero text on scroll-in or via animation. For block cloning specifically, set onlyMainContent: false and waitFor: 4000, and add formats: ["markdown", "screenshot@fullPage"] so you get the full-page screenshot, not just the viewport.
5. The viewport screenshot misses everything below the fold. Firecrawl's default screenshot is viewport-sized. For a tall page, the model never sees the comparison section, the pricing tier, the footer CTA. Switch to full-page (screenshot@fullPage in Firecrawl v1 — verify the exact API key name in their current docs), then either send the full image or slice it into 2–3 overlapping panels and send all of them as separate image_url parts.
6. No two-pass "extract then generate" structure. Today it's one call: "here's a URL, here's a screenshot, here's the user prompt, write the block." This puts the model in the impossible position of (a) extracting style/structure from raw markdown+image AND (b) generating new content matching that style — in a single 4096-token response. Split it:

Pass 1 (cheap, GPT-4o-mini): "Extract from this URL and screenshot: structural blocks (ordered list of section types and their layouts), typography hierarchy, color palette with hex, 5 voice descriptors, 6 example headlines verbatim, 6 example body sentences verbatim, density rating (sparse/balanced/dense), aesthetic descriptors." Return as JSON.
Pass 2 (GPT-4o): "Generate the block. Use this extracted brand profile as a strict constraint. Headlines must follow the patterns shown. Density must match." Pass the extracted JSON in as a structured brand profile. This is how good design-clone tools work, and it usually doubles perceived fidelity. The extra ~$0.002 per generation is nothing compared to the cost of a bad output that the user throws away.
