# Prompt 5 — Credential encryption at rest for `lp_integrations`

## Context

The pre-launch audit (`/outputs/pre-launch-audit.md` item S1) flagged that integration credentials stored in `lp_integrations.config` (jsonb) are plaintext, despite a code comment in `lib/db/src/schema/sfdcIntegration.ts` claiming "encrypted at rest." Charlotte's decided to fix this pre-launch rather than defer it.

**Scope-narrowing fact (verified):** the SFDC OAuth integration is not yet live. The `sfdc_connections`, `sfdc_leads`, etc. tables exist but no real tenant has connected an SFDC org, so no real OAuth tokens are stored. The only credentials actually present in prod today are in the `lp_integrations.config` jsonb column: Marketo (clientId/clientSecret), and potentially Google Sheets (serviceAccountEmail/privateKey) and Asana (PAT).

That means the encryption work is **one table, one column, a handful of rows**. This is genuinely a one-day fix, not a multi-day project.

**Branch:** work on `staging`.

**Use the `STAGING_DATABASE_URL` pattern:** validate the migration and the encrypt/decrypt round-trip against the staging Neon branch before applying to prod. Same pattern Replit just established for Prompt 2 v2.

## What to build

### 1. New file: `artifacts/api-server/src/lib/encryption.ts`

Standard AES-256-GCM authenticated encryption with a versioned envelope so future migrations can identify what's been encrypted vs. what's still plaintext.

```ts
import { randomBytes, createCipheriv, createDecipheriv, CipherGCMTypes } from "node:crypto";

const ALGO: CipherGCMTypes = "aes-256-gcm";
const VERSION = "v1";
const IV_LENGTH = 12; // 96 bits, recommended for GCM
const AUTH_TAG_LENGTH = 16; // 128 bits

/**
 * Master encryption key for stored credentials. 32 raw bytes, base64-encoded
 * in the env var. Generate with: `openssl rand -base64 32`.
 *
 * Loss of this key = inability to decrypt every stored integration credential.
 * Back this up out-of-band (Replit secrets export, 1Password, etc.). Rotation
 * is a future capability — for v1 the key is static.
 */
function getKey(): Buffer {
  const raw = process.env.CREDENTIAL_ENCRYPTION_KEY;
  if (!raw) {
    if (process.env.NODE_ENV === "production") {
      throw new Error(
        "CREDENTIAL_ENCRYPTION_KEY is required in production. " +
        "Generate with: openssl rand -base64 32"
      );
    }
    // Non-prod: use a deterministic dev key so test fixtures work. Logged loudly.
    console.warn(
      "[encryption] CREDENTIAL_ENCRYPTION_KEY not set — using dev fallback. " +
      "Never run this way in production."
    );
    return Buffer.from("dev-key-not-for-production-use-32".padEnd(32, "0"));
  }
  const key = Buffer.from(raw, "base64");
  if (key.length !== 32) {
    throw new Error(
      `CREDENTIAL_ENCRYPTION_KEY must be 32 bytes (base64-encoded). Got ${key.length} bytes.`
    );
  }
  return key;
}

/**
 * Encrypt a credential string. Returns a versioned envelope:
 *   "v1:" + base64(iv || ciphertext || authTag)
 *
 * The version prefix lets future migrations identify encrypted vs. plaintext
 * values and lets a future v2 use a different algorithm without ambiguity.
 */
export function encryptCredential(plaintext: string): string {
  if (typeof plaintext !== "string") {
    throw new Error("encryptCredential: input must be a string");
  }
  if (plaintext === "") return ""; // empty strings round-trip as-is
  
  const iv = randomBytes(IV_LENGTH);
  const cipher = createCipheriv(ALGO, getKey(), iv);
  const ciphertext = Buffer.concat([
    cipher.update(plaintext, "utf8"),
    cipher.final(),
  ]);
  const authTag = cipher.getAuthTag();
  
  const envelope = Buffer.concat([iv, ciphertext, authTag]);
  return `${VERSION}:${envelope.toString("base64")}`;
}

/**
 * Decrypt a credential string. Accepts:
 *   - "v1:base64..." → decrypts via AES-256-GCM
 *   - bare string (no version prefix) → returned as-is (legacy plaintext, during migration)
 *   - "" → returned as ""
 *
 * The plaintext fallback lets us deploy the decrypt-on-read code BEFORE the
 * backfill migration runs, so partial rollouts don't break.
 */
export function decryptCredential(value: string | null | undefined): string {
  if (value == null || value === "") return value ?? "";
  if (typeof value !== "string") {
    throw new Error("decryptCredential: input must be a string");
  }
  
  // Legacy plaintext path — return as-is
  if (!value.startsWith(`${VERSION}:`)) return value;
  
  const envelope = Buffer.from(value.slice(VERSION.length + 1), "base64");
  if (envelope.length < IV_LENGTH + AUTH_TAG_LENGTH) {
    throw new Error("decryptCredential: envelope too short");
  }
  
  const iv = envelope.subarray(0, IV_LENGTH);
  const authTag = envelope.subarray(envelope.length - AUTH_TAG_LENGTH);
  const ciphertext = envelope.subarray(IV_LENGTH, envelope.length - AUTH_TAG_LENGTH);
  
  const decipher = createDecipheriv(ALGO, getKey(), iv);
  decipher.setAuthTag(authTag);
  const plaintext = Buffer.concat([
    decipher.update(ciphertext),
    decipher.final(),
  ]);
  return plaintext.toString("utf8");
}

/**
 * Identify which keys in an integration's `config` jsonb should be treated as
 * credentials and therefore encrypted. Whitelist approach: explicit list per
 * provider, so we don't accidentally encrypt display labels or IDs.
 */
const CREDENTIAL_FIELDS_BY_PROVIDER: Record<string, string[]> = {
  marketo: ["clientSecret"],
  salesforce: ["clientSecret"],
  google_sheets: ["privateKey"],
  asana: ["pat"],
  // Add new providers here as integrations ship.
};

export function isCredentialField(provider: string, fieldName: string): boolean {
  return (CREDENTIAL_FIELDS_BY_PROVIDER[provider] ?? []).includes(fieldName);
}

/**
 * Encrypt all credential fields within a config object. Returns a NEW object;
 * does not mutate the input. Non-credential fields are returned as-is.
 */
export function encryptConfigCredentials(
  provider: string,
  config: Record<string, unknown>,
): Record<string, unknown> {
  const credentialFields = CREDENTIAL_FIELDS_BY_PROVIDER[provider] ?? [];
  const out: Record<string, unknown> = { ...config };
  for (const field of credentialFields) {
    const value = config[field];
    if (typeof value === "string" && value !== "") {
      out[field] = encryptCredential(value);
    }
  }
  return out;
}

/**
 * Decrypt all credential fields within a config object. Returns a NEW object;
 * does not mutate the input. Already-plaintext fields pass through unchanged
 * (legacy support during the backfill window).
 */
export function decryptConfigCredentials(
  provider: string,
  config: Record<string, unknown>,
): Record<string, unknown> {
  const credentialFields = CREDENTIAL_FIELDS_BY_PROVIDER[provider] ?? [];
  const out: Record<string, unknown> = { ...config };
  for (const field of credentialFields) {
    const value = config[field];
    if (typeof value === "string" && value !== "") {
      out[field] = decryptCredential(value);
    }
  }
  return out;
}
```

### 3. Wire it into the read path(s)

Everywhere `lp_integrations.config` is read and used as a live credential:

- `artifacts/api-server/src/lib/exportDestinations.ts::getIntegration` — decrypt before returning
- `artifacts/api-server/src/lib/notifications.ts` — wherever Marketo config is loaded for actual API calls
- Any other callers (grep for `lp_integrations` reads)

Pattern:
```ts
import { decryptConfigCredentials } from "../lib/encryption";

const row = await db.execute(sql`SELECT config FROM lp_integrations WHERE ...`);
const config = row.rows[0]?.config as Record<string, unknown>;
const decryptedConfig = decryptConfigCredentials(provider, config);
// Use decryptedConfig from here on.
```

The decrypt path falls through plaintext values unchanged (via the version-prefix check in `decryptCredential`), so the read path can ship BEFORE the backfill runs without breaking.

### 4. Backfill script

New file: `artifacts/api-server/scripts/backfill-encrypt-integrations.ts`

```ts
import { Pool } from "pg";
import { encryptConfigCredentials, isCredentialField } from "../src/lib/encryption";

const url = process.env.STAGING_DATABASE_URL ?? process.env.NEON_DATABASE_URL;
if (!url) {
  console.error("Need STAGING_DATABASE_URL or NEON_DATABASE_URL");
  process.exit(1);
}

const pool = new Pool({ connectionString: url, ssl: { rejectUnauthorized: false } });

async function main() {
  const { rows } = await pool.query(
    `SELECT id, provider, config FROM lp_integrations WHERE config IS NOT NULL`
  );
  
  console.log(`Found ${rows.length} integration rows to inspect.`);
  
  let encrypted = 0, skipped = 0;
  for (const row of rows) {
    const { id, provider, config } = row;
    if (!config || typeof config !== "object") {
      skipped++;
      continue;
    }
    
    // Check if any credential field is still plaintext (no v1: prefix)
    const needsEncryption = Object.entries(config).some(
      ([field, value]) =>
        isCredentialField(provider, field) &&
        typeof value === "string" &&
        value !== "" &&
        !value.startsWith("v1:")
    );
    
    if (!needsEncryption) {
      skipped++;
      continue;
    }
    
    const newConfig = encryptConfigCredentials(provider, config);
    await pool.query(
      `UPDATE lp_integrations SET config = $1::jsonb WHERE id = $2`,
      [JSON.stringify(newConfig), id]
    );
    encrypted++;
    console.log(`  Encrypted credentials for integration ${id} (${provider})`);
  }
  
  console.log(`Done. Encrypted ${encrypted}, skipped ${skipped} (already encrypted or no credentials).`);
  await pool.end();
}

main().catch((err) => {
  console.error(err);
  process.exit(1);
});
```

```bash

```

### 7. Tests

New file: `artifacts/api-server/src/lib/encryption.test.ts`

```ts
import { describe, it, expect } from "vitest";
import {
  encryptCredential,
  decryptCredential,
  encryptConfigCredentials,
  decryptConfigCredentials,
} from "./encryption";

describe("encryption", () => {
  it("round-trips a string", () => {
    const original = "super-secret-marketo-client-secret-abc123";
    const encrypted = encryptCredential(original);
    expect(encrypted).toMatch(/^v1:/);
    expect(encrypted).not.toContain(original);
    expect(decryptCredential(encrypted)).toBe(original);
  });
  
  it("produces different ciphertext for same plaintext (random IV)", () => {
    const a = encryptCredential("hello");
    const b = encryptCredential("hello");
    expect(a).not.toBe(b);
    expect(decryptCredential(a)).toBe("hello");
    expect(decryptCredential(b)).toBe("hello");
  });
  
  it("rejects tampered ciphertext", () => {
    const encrypted = encryptCredential("hello");
    const tampered = encrypted.slice(0, -4) + "XXXX";
    expect(() => decryptCredential(tampered)).toThrow();
  });
  
  it("passes through plaintext (legacy) values unchanged", () => {
    expect(decryptCredential("not-a-v1-prefix")).toBe("not-a-v1-prefix");
    expect(decryptCredential("")).toBe("");
  });
  
  it("encrypts only credential fields in a marketo config", () => {
    const config = {
      munchkinId: "123-ABC-456",
      clientId: "abc123",
      clientSecret: "super-secret",
    };
    const encrypted = encryptConfigCredentials("marketo", config);
    expect(encrypted.munchkinId).toBe("123-ABC-456");
    expect(encrypted.clientId).toBe("abc123");
    expect(encrypted.clientSecret).toMatch(/^v1:/);
    
    const decrypted = decryptConfigCredentials("marketo", encrypted);
    expect(decrypted.clientSecret).toBe("super-secret");
  });
  
  it("passes through unknown providers unchanged", () => {
    const config = { whatever: "value" };
    expect(encryptConfigCredentials("unknown-provider", config)).toEqual(config);
  });
});
```

Integration test (against real DB): write a Marketo config via `upsertIntegration`, read it back via `getIntegration`, verify the credential is decrypted correctly. Verify the row in the DB has the encrypted value (`v1:` prefix).

## What NOT to do

- **Don't encrypt SFDC tokens.** The table is empty. There's nothing to encrypt. Just fix the misleading comment so future engineers don't think they're protected by encryption that doesn't exist.
- **Don't introduce KMS or per-tenant keys.** Single static env-var key is correct for v1. KMS is a future improvement when you're at SOC 2 maturity.
- **Don't add new feature flags or gradual rollout.** ~12 rows total. One-shot encrypt-in-place is correct. The plaintext-fallback in `decryptCredential` covers the brief window between code deploy and backfill completion.
- **Don't write your own crypto.** Use Node's `node:crypto` module. The code above uses the standard library. Resist any temptation to "optimize" or "simplify" the encryption logic.
- **Don't store the key anywhere it'll be logged.** Don't log it on boot, don't echo it in error messages, don't include it in any Sentry breadcrumb.
- **Don't lose the key.** Loss = inability to decrypt every stored credential = every integration breaks until the key is recovered. Back it up in at least two places that aren't both in Replit.
- **Don't rotate the key in v1.** Rotation requires re-encrypting all rows with the new key. That's a follow-on capability (re-encrypt-with-new-key script). For now the key is static. If you ever need to rotate, the version-prefix design means `v2:` can use a new key and the migration handles the transition.

The misleading "encrypted at rest" comment becomes true. The encryption helpers exist for any future credential storage (when SFDC OAuth actually ships, when HubSpot adapter is built, when any future integration needs to store secrets). The launch-blocker security gap from the audit is closed.
