#603 first — recipient failure safety-net (well-specified, no product ambiguity)
Build this independently — it's a clean defensive layer over the existing dispatcher. Guarantee no silent recipient drop when a workflow matches but enrollment/claim fails before any send, without risking a double-send.
Specifically: when a workflow run's INSERT into notification_sends for the dedupe-claim row fails for a transient reason (DB connection blip, conflict on a race), the recipient currently gets silently skipped. Idempotency contract: the retry must use the same dedupe_key per recipient as the original attempt. The existing UNIQUE(dedupe_key, channel) index prevents double-sends; the retry just tries to claim the row that previously failed to insert.

#602 — Scheduled + Audience trigger execution
Product decisions (resolved):
Scheduled trigger supports both one-time and recurring. Recurring uses preset cadences, not raw cron:

Daily at HH:MM — e.g. every day at 8:00 AM
Weekly on {day} at HH:MM — e.g. every Monday at 9:00 AM
Monthly on day-N at HH:MM — e.g. the 1st of every month at 10:00 AM (with end-of-month handling for "31st" on shorter months → falls back to the last day)

Default timezone is UTC for v1. Show the timezone explicitly in the UI ("Sends at 09:00 UTC, which is 04:00 ET / 02:00 MT"). Per-template timezone configuration is a v1.1 addition; UTC keeps the engine predictable.
Audience trigger supports all four filter dimensions with AND combinator:

Plan tier — multi-select of free | starter | growth | scale | enterprise
Role — multi-select of tenant role values (owner / admin / editor / viewer, plus superadmin as a synthetic option)
Specific tenants/workspaces — multi-select picker over the tenants table
Everyone — explicit option meaning "no filter, the whole platform"

Filter combinator is AND across dimensions. Within a dimension it's OR (multi-select). Example: plan ∈ {growth, scale} AND role ∈ {owner, admin} → growth or scale tenant admins/owners.
The "how often" behavior (the decision that shapes the schema, UI, and engine producers):

One-time scheduled: everyone in the audience at the scheduled moment gets it once. Resolved at fire time; no backfill, no re-fire.
Recurring scheduled: each occurrence sends to whoever's in the audience at that moment. Someone who joins next week gets next week's send only. Nobody gets the same occurrence twice (per-occurrence dedupe).
Audience trigger: each person gets it once, when they FIRST match the filter. Doesn't re-fire if they leave and re-enter the filter, doesn't backfill historical matches at first deploy. This is the standard marketing-automation behavior.

This is the recommended marketing-automation default. If a future use case requires "recurring sends to only brand-new matches" or "audience triggers that re-fire on every match," add it as a re_fire_mode field on the trigger config later — don't bake either alternative into v1.
Engine producers (the part that doesn't exist yet):
The data model already has trigger_type IN ('event', 'scheduled', 'audience') and a config JSONB column. Event triggers work. Scheduled and audience need producers that turn config + current state into per-recipient enrollments.
Two new modules in artifacts/api-server/src/lib/:

audienceResolver.ts — pure function resolveAudience(filter: AudienceFilter, scope: { platform: true } | { tenantId: number }): Promise<Recipient[]>. Builds a Drizzle query against tenants + app_users based on filter dimensions, returns matched recipients. Reusable by both scheduled and audience producers. Has a previewAudienceCount(filter) companion for the UI's "Recipient count preview" before save.
scheduledTickProducer.ts — runs on the existing 60s sweep. For each active workflow with trigger_type='scheduled':

Compute the next due-time from config.cadence + last_fired_at
If now() >= next_due_at AND last_occurrence < next_due_at: resolve audience, enroll recipients (one workflow run + per-recipient dedupe keys per occurrence), stamp last_fired_at = now().
Per-occurrence dedupe: dedupe_key = ${workflow_id}:${recipient_id}:${occurrence_id} where occurrence_id is the ISO-formatted scheduled time (e.g. 2026-06-01T09:00:00Z). UNIQUE constraint on notification_workflow_run_recipients prevents double-enrollment within a single occurrence.


audienceTickProducer.ts — runs on the same 60s sweep. For each active workflow with trigger_type='audience':

Resolve audience as of now()
For each recipient: check if they're already in notification_workflow_run_recipients for this workflow → if not, enroll them. If yes, skip.
Idempotency: UNIQUE(workflow_id, recipient_id) for audience-type runs ensures one-fire-per-match, ever.



Both producers run lazy-on-read inside the existing sweep — no new cron infra. Same pg_try_advisory_xact_lock + FOR UPDATE SKIP LOCKED pattern the existing workflowEngine.ts:269+ sweep uses.
Config schema (on existing config JSONB column, no migration needed):
ts// Scheduled trigger config
interface ScheduledConfig {
  cadence: { type: "one_time"; fire_at: string /* ISO UTC */ }
         | { type: "daily"; time: string /* "HH:MM" */ }
         | { type: "weekly"; day: 0 | 1 | 2 | 3 | 4 | 5 | 6; time: string }
         | { type: "monthly"; day_of_month: number /* 1..31, EOM-clamped */; time: string };
  audience: AudienceFilter;
}

// Audience trigger config
interface AudienceConfig {
  audience: AudienceFilter;
}

interface AudienceFilter {
  scope: "platform" | "tenant_subset";
  plan?: Plan[];           // multi-select; undefined = no filter on this dim
  role?: Role[];           // multi-select; undefined = no filter
  tenant_ids?: number[];   // multi-select when scope === "tenant_subset"
  // If all dims are undefined → "Everyone" filter (no AND constraints)
}
