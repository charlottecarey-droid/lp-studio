Task: Fix the refresh-copy endpoints to use brand + brief, not just existing block content

Context Most of our AI text flows work correctly: AI email draft, AI Content Brief generation, prompt-to-page assembly all pull from the brand voice profile and produce on-brand output. Three flows have a specific bug:





Block-level "refresh copy" button — refreshes the copy on a whole block. Today it uses the block's existing content as the only source. When the block was pulled from the central block catalog (and arrived with generic placeholder copy), refreshing produces more generic copy because there's nothing on-brand to amplify.



Generate block - pulls from the block example. it should pull from brand settings and be on brand/color/fonts unless the user explicitly asks otherwise.



SEO Metadata gen pulls from the brand settings instead of page settings/brief. it needs to pull from the page/brief since its specific to the page (needs to be on brand too but page is first priority

None of the endpoints load the tenant's brand voice profile or the page's active brief. They should.

This is not a refactor task. Other AI flows already work — leave them alone. Just fix these three endpoints.

Find and show me the three endpoints: the route, the function that builds the LLM prompt, and the OpenAI call.

Implementation

For each of the two endpoints:

Build the prompt from three layers:

[System] Brand voice profile (tone, formality, vocabulary, signature phrases, forbidden phrases, one-sentence brand summary).
         Mirror the serialization pattern from the AI Content Brief flow.

[Context] Active brief if one exists (audience, pain points, value props, voice).
          If no brief, omit this section entirely — do not invent.

[Task]   Block context (block type, role on page, surrounding blocks' summary)
         + current content (as a *reference*, not the only source)
         + user's action (refresh / rewrite / shorten / lengthen / change tone)
         + output format expectations.

Key behavioral change: the existing content becomes a reference the model can ignore or rewrite freely, not the primary source. The brand voice and brief drive the output; existing content just signals what slot/role we're filling.

For field-level Sparkle specifically:





Also include 2–3 surrounding fields' content as context so the rewritten field still fits the block's local rhythm.



Respect the Sparkle mode (rewrite vs shorten vs lengthen vs change tone) — these are different prompts internally, just all sharing the same brand+brief injection.

Cross-cutting





Backward compat: input/output shape of both endpoints stays the same. Only the LLM prompt changes.



Concurrency: reuse the existing OpenAI semaphore from the brand-import work. Don't introduce parallel rate limiting.



No feature flag needed — this is a bug fix, not a new behavior. The old behavior was wrong; the new behavior is what users assumed was happening.



If brand voice profile is missing for a tenant, fall back to the current behavior (regenerate from existing content). Don't error out. Add a one-time log line so we know which tenants need their brand voice trained.



Observability: log every refresh-copy call with { endpoint, tenant_id, brand_id, brief_id?, block_type, sparkle_mode?, prompt_tokens, completion_tokens, success }. We'll want this to spot regressions.
