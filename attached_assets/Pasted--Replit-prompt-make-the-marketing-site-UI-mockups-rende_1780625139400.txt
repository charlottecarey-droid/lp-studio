# Replit prompt — make the marketing-site UI mockups render well on mobile

Hi! The new LP Studio marketing site (homepage at `/`, plus `/features`, `/for-marketing`, `/for-sales`, `/pricing`, `/compare`) reads great on desktop but the in-page UI mockups break on mobile — fixed-pixel browser-chrome wrappers overflow the viewport, multi-column dashboards squish unreadably, and modal overlays positioned with `right: 0` slide off-screen. Please do a full mobile-fix pass across the marketing components below.

**Scope:** only `artifacts/lp-studio/src/marketing/**`. Do **not** touch the app shell, the in-product UI, or any backend code.

---

## Strategy (read this first)

Most of the in-page mockups are decorative — they exist to make the marketing copy feel concrete. On mobile, fidelity matters less than legibility. So the default approach for each mockup should be **one of these three**, picked per-component:

1. **Reflow responsively** — when the mock has a small number of elements that can stack into a single column (e.g. card grids, color-token rows, type pairings). Use Tailwind responsive prefixes (`md:`, `lg:`) and CSS Grid breakpoints. This is the preferred option when feasible.

2. **Horizontal-scroll the chrome** — when the mock is genuinely table-shaped or dashboard-shaped (IdentityWedge analytics table, SalesConsoleEmbed dashboard, the Compare matrix on `/compare`). Wrap the inner content in `overflow-x: auto` with a fixed minimum width on the inner container, so a single-finger swipe reveals the rest. Add a faint right-edge gradient mask to telegraph that there's more.

3. **Hide the chrome on mobile, show a simpler text/stat alternative** — when the mock is too complex to scale down meaningfully and the surrounding copy already carries the message (AssembleSceneV2 scroll demo, BuilderEmbed, AI Briefing modal pop-over). Use `hidden md:block` on the chrome wrapper, and add an `md:hidden` block above it that renders the same idea in 2–3 sentences with maybe an icon and a single stat. The marketing copy + a small text card is fine — don't try to recreate the chrome at a smaller size.

**What MUST stay responsive at every breakpoint (320px and up):**
- All headlines, subheads, body copy, bullet lists, CTA buttons
- Navbar (already mostly fine — verify the mobile menu works)
- Footer link grid (should collapse from 4 columns → 2 → 1)
- Pricing tier cards (should stack 1-per-row on mobile)
- FAQ accordion (already a single column, just verify the answer text wraps)
- Hero headline + PromptCard input (text + button must reflow, but the Mad Libs animation can pause/freeze on small screens)
- Use the `var(--cream)` body background everywhere; never let device-frame INK_2 leak out

## Components to fix, with specific guidance

### 1. `HeroScene.tsx` + `PromptCard.tsx`

- PromptCard: the prompt input + Generate button row should stack vertically on `<md`; suggestion chips should wrap to multiple lines, not horizontal-scroll

### 2. `AssembleSceneV2.tsx` (the big scroll-driven page-assembles demo)

**Already works on mobile** — the component checks `vw < 768` and collapses the left/right builder sidebars to width 0 on small screens (line 1004 in AssembleSceneV2.tsx: `const isMobile = vw < 768`). The only adjustment needed:

- **Raise the `isMobile` breakpoint** from `768` to a higher value so the sidebars collapse *as soon as they start overlapping the canvas*, not only at phone widths. The canvas is 960px internally; the two sidebars together take 240 + 280 = 520px. The device frame should hide sidebars when the viewport is narrower than roughly `canvas + sidebars + a little breathing room` — try `vw < 1100` and tune from there. The intent: by the time the sidebars would start visually crowding the canvas, they're already gone.
- Do not replace the demo with a static poster — the scroll mechanic works fine without the sidebars.

### 3. `UseCases.tsx` (4-card grid with mini page previews)

- The outer grid is already `grid-cols-1 md:grid-cols-2` (line 491) — no change needed at the outer level.
- Each card's `<Frame>` + `<BrowserBar>` mini-page-preview has fixed pixel padding/widths inside — let it scale down by replacing fixed `width` styles with `width: 100%` on the inner containers, and letting browser-bar segment widths use `flex: 1` instead of fixed px.
- If any text inside the mini-previews becomes unreadably small below 480px, just hide that inner content (`hidden sm:block`) and show the card with title + bullets only.

### 4. WhatsInside zigzag (inline in `home.tsx`, with `BrandVisual` / `MarketingVisual` / `SalesVisual` / `CompareVisual`)

The zigzag rows already use `grid-cols-1 md:grid-cols-2` so the structure stacks. Issues are inside the visual cards:

But the 2-column "Type pairing" grid (`gridTemplateColumns: "1fr 1fr"`) should become a single column below 480px (`grid-cols-1 xs:grid-cols-2`). The voice-axis dots row at the bottom has a 3-column layout (70px label / 1fr track / 70px label) — that should drop the labels and just show the track + a single inline label on small screens.
- **MarketingVisual**: the stat strip is `grid-cols-3` — keep it 3 columns but shrink the numbers (fontSize 18→14). The variant rows have `gap: 11` between thumbnail + label + bar + percentage — on `<sm` this overflows. Either drop the variant thumbnail (`VariantThumb`) on mobile and let the label + bar carry the weight, or stack the bar UNDER the label.
- **SalesVisual**: the account header has a 3-column layout (logo + name + engagement gauge). On mobile, drop the engagement gauge below the rest as a third row, or absorb it into a single-line stat.

Also: the section header spine line (the absolutely-positioned 1px vertical line at `left: -4`) only makes sense in the md+ zigzag layout — hide it on mobile (`hidden md:block`).

The marker tile (the indigo 36×36 square with `01`/`02`/`03`/`04`) is positioned at `left: -22` from the text column — on mobile, where everything stacks, this marker overflows the viewport. Hide it on mobile (`hidden md:flex`) and use the small inline marker that's already in the design as the `md:hidden` fallback.

## Things you should NOT do

- Don't redesign the desktop layouts — they're fine
- Don't touch the in-product app (anything outside `src/marketing/`)
- Don't add new component dependencies (no react-responsive, no react-device-detect — Tailwind breakpoints + CSS media queries cover everything here)
- Don't break SSR — the prerender script (`scripts/prerender-marketing.mjs`) bakes the desktop HTML at build time. Any responsive-only logic that uses `window.innerWidth` must guard for SSR with `typeof window !== "undefined"` and default to the desktop branch during prerender. Better: use CSS media queries (Tailwind responsive prefixes) wherever possible — they don't need a hydration cycle to apply.
- Don't gate visibility with JS measurements when CSS can do it. Reach for `useState(window.innerWidth)` only when you actually need to change behavior (e.g. disabling the AssembleScene scroll listener on mobile, disabling the auto-open of ContactDetailModal).
