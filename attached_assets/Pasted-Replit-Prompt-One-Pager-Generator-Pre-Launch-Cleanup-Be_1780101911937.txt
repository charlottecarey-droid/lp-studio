Replit Prompt — One-Pager Generator: Pre-Launch Cleanup + Beta Gating
A scoped, surgical fix to make the one-pager generator safe to ship to non-Dandy tenants at launch. Two layers in one prompt:

Pre-launch cleanup — eliminate the four concrete Dandy leaks that even the existing scrubBrand() regex doesn't catch (asset imports, default URLs, template labels, overlay field labels).
Beta gating — for non-Dandy tenants, hide the two most Dandy-coded built-in templates and label the feature "(beta)" so the launch story matches reality.

The defensive base is already strong. lib/one-pager-types/src/generators.ts:139-163 (scrubBrand) maps "Dandy" / "Dandy Insights" / "Dandy Practice Agreement" / "dental lab" / "DSO" / "meetdandy.com" → brand-config equivalents at PDF generation time, no-op for Dandy. Most body copy is safe. The remaining leaks are things scrubBrand can't see — bitmap assets, default form values, admin-visible UI strings, and built-in template labels stored as TypeScript literals.
Five concrete things this prompt fixes:

Four hardcoded Dandy product-screenshot imports in sales-one-pager.tsx:3-6 used as PDF header-image fallbacks (ai-scan-review-news.jpg, ai-scan-review-clinical.png, dandy-dso-enterprise-data.webp, dandy-scanner-transparent.png) — non-Dandy tenants without uploaded custom images get Dandy dental UI in their PDFs
defaultValue: "https://meetdandy.com" on QR + link form fields in sales-one-pager-templates.tsx:187, 211, 214 — new templates created by non-Dandy admins ship with Dandy URLs baked into the field defaults
"Summary of Dandy Agreement terms" template card description in sales-one-pager-templates.tsx:155 and "Dandy Evolution" template label in sales-one-pager-templates.tsx:152 — admin-visible UI strings that don't reach the PDF (so scrubBrand never sees them) but show in the template picker
Hardcoded "Dandy Logo" / "Dandy & DSO Name" overlay field labels seeded by cloneFieldsForBuiltin (sales-one-pager-templates.tsx:160-189) when admins clone a built-in template — labels carry through to the editor and to the saved template JSON
Two built-in templates that are too Dandy-coded for scrubBrand to fully neutralize (comparison / Dandy Evolution and agreement-summary / Agreement Summary) — gated to Dandy-only with a per-tenant feature check; non-Dandy tenants see only the brand-neutral built-ins (ROI, 90-Day Pilot, Partner Practices, Partner 2) plus the Custom Template overlay tool

Estimated scope: ~1.5–2 days of Replit work.
Out of scope (deferred to v1.1): a structured content-authoring UX for new one-pager types. Today's "Custom templates" path is a PDF overlay positioning tool, not a content authoring tool — admins can drop fields on a background PDF but can't write body copy / stats / structured sections without a code change to generators.ts. That's a ~3-week post-launch project.

Why this is the right scope
Three specific decisions worth flagging:
1. Beta gating > full surgery. The audit suggested rewriting the Dandy-coded built-ins to be brand-agnostic. That's a 1-2-week project and the structural assumptions in comparison and agreement-summary (before/after Dandy customer journey, Dandy Practice Agreement) don't translate cleanly to other industries even with copy rewrites. Cleaner to gate them and call it beta. The four remaining built-ins (roi, pilot, new-partner, partner2) plus the Custom Template overlay tool give non-Dandy tenants a credible feature surface today.
2. Brand-driven assets, not bitmap renames. The four hardcoded Dandy header images are stored in the src/assets folder as part of the frontend bundle. The fix isn't "swap in neutral bitmaps for non-Dandy tenants" (which still bundles Dandy's screenshots in everyone's app); it's "move asset references to brand config so they're per-tenant data." The neutral fallback is a generated rect + wordmark, no bitmap — better to render minimally than to ship Dandy's screenshots to every customer's browser.
3. Don't mutate saved data. Existing custom templates saved by any tenant stay intact. The cleanup applies to defaults for new templates and to render-time UI strings. This avoids a class of regressions where a "fix" rewrites stored data in a way that breaks an existing customer setup we don't know about.
What this prompt explicitly doesn't do

Doesn't build the structured content authoring UX for new one-pager types. That's the bigger ~3-week post-launch project. Today's Custom Template tool is overlay-only; admins can't define new body-copy templates without a code change to generators.ts. We accept this for v1, label it "(beta)" in the marketing copy, and ship the authoring UX in v1.1.
Doesn't rewrite the Dandy-coded built-ins to be brand-agnostic. Gating > rewriting for these two.
Doesn't touch the AI Draft Email (separate ~2-4 hour fix for dental publication names + DSO Perplexity queries, tracked in sales-console-audit.md).
Doesn't touch the microsite generator (separate ~1-1.5 day fix scoped in replit-prompt-brand-defined-segments.md).
