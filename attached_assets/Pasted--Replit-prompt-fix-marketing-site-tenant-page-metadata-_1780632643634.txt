## Step 2 — Regenerate `opengraph.jpg` at 1200×630

The current OG image lives at `artifacts/lp-studio/public/opengraph.jpg` and is 1280×720 (about 61KB, JPEG). Facebook's official OG recommendation is **1200×630** (1.91:1 ratio); Slack, LinkedIn, Twitter all prefer this size. 1280×720 is the YouTube standard and will letterbox or get re-cropped on some surfaces.

Two options to regenerate, in order of preference:

### Option A — Resize the existing artwork (fast)

If the source artwork exists in a designable format (Figma export, source PSD/Sketch, or the original PNG before JPEG compression), re-export at exactly 1200×630. Save back to `artifacts/lp-studio/public/opengraph.jpg` as JPEG, quality 85–90, target file size under 100KB.

### Option B — Regenerate the 1200×630 from the current JPEG (acceptable but lower fidelity)

If no source artwork exists, use `sharp` (already available in node_modules of the api-server workspace or installable as a dev dep):

```bash
cd artifacts/lp-studio
npx sharp -i public/opengraph.jpg -o public/opengraph.jpg \
  --resize 1200 630 --fit cover --position center
```

This center-crops the existing 1280×720 down to 1200×630. Verify the result visually — if anything important is at the very top or bottom edge of the current image, it might get cropped; in that case, manually re-do it from source.

# Part C — Tenant OG metadata: cascade + per-page editor + Dandy seed

LP Studio tenants publish landing pages and need to share cleanly on social. Build a **tenant-default → per-page** cascade so most pages inherit the tenant's brand defaults and individual pages can override only when they need to. Bring the per-page editor to parity with what the marketing site itself needs (char-count helpers, dimension warnings, share-card preview). Seed Dandy as the first tenant to use the new defaults system.

## Step C.1 — Audit the existing per-page metadata editor

Find the in-app per-page settings UI that holds the page's OG fields. Search for `og:title`, `og:description`, `ogImage`, `metaDescription`, or wherever `lp_pages` columns like `meta_title` / `meta_description` / `og_image` get edited. Likely paths:

- `artifacts/lp-studio/src/pages/builder/...` (the builder's settings drawer)
- `artifacts/lp-studio/src/pages/pages/[id]/settings.tsx` or similar
- The page-detail view's settings tab

Document the current state in a 5-line summary in the PR description: what fields exist, what validation runs (if any), what the share-preview surface looks like (or if there isn't one).

## Step C.2 — Add the same affordances the marketing site needs

For each OG field in the editor, add the same UX the audit tool would want:

- **Title field**: live character count. Green at 50–60. Yellow under 50 or 61–70. Red above 70. Below 50: tooltip "Most share cards truncate around 60 chars — too short reads thin." Above 70: tooltip "Facebook truncates around 60 chars; Twitter around 70."
- **Description field**: live character count. Green at 110–160. Yellow under 110 or 161–200. Red above 200. Tooltip text similar to above.
- **OG image upload**: when a user uploads, run a client-side check on dimensions. If not 1200×630, surface an inline warning (not a blocker) — "Recommended size is 1200×630. Your image is `<actual>` — it may letterbox or crop on some platforms." Offer a "Resize to 1200×630" one-click button that does a center-crop server-side via `sharp` (same call pattern as the marketing OG resize in Part A).
- **Live share-card preview**: a small mock that renders what the OG card looks like on Facebook / LinkedIn / Twitter (use the user's actual title + description + image with the standard share-card visual treatment). 240px wide preview is enough — it's a sanity check, not a design tool.

## Step C.3 — Tenant-default OG metadata + cascade

Per-page metadata overrides should be the exception, not the rule. Most pages should inherit the tenant's brand-default OG so every page a tenant publishes shares cleanly without per-page work. Add a tenant-level OG defaults layer.

### Schema

Add columns to `tenants` in `lib/db/src/schema/tenants.ts`:

- `default_og_title` — text, nullable. Either a plain string (used as-is) OR a template with `{{page_title}}` token (e.g., `"{{page_title}} — Meet Dandy"`). Keep it simple: if it contains `{{page_title}}`, substitute the page's display title; otherwise use the literal string.
- `default_og_description` — text, nullable. Plain string.
- `default_og_image_url` — text, nullable. URL to a 1200×630 image stored in the tenant's asset bucket.

Migrate any existing tenants with `null` defaults — they'll fall through to the LP Studio system fallback.

### Cascade order

For every published tenant page, resolve OG fields in this order (first non-null wins):

1. Per-page field on `lp_pages` (`meta_title` / `meta_description` / `og_image`)
2. Tenant default (`tenants.default_og_title` / `default_og_description` / `default_og_image_url`)
3. Derived from page content (H1 → title, first sentence → description, brand-imported hero → image)
4. System fallback (LP Studio composite placeholder)

Implement this as a single resolver helper, e.g. `resolvePageOG(pageId): { title, description, image, width, height }`, and have the published-page rendering layer call it. Don't duplicate the cascade logic in two places.

### Tenant settings UI

Add a "Default share card" panel to the tenant's brand-settings area (same surface where they upload logos / set colors). Fields:

- "Default OG title" — text input with the same live char-count helper as the per-page editor (50–60 green). Includes a small note: "Use `{{page_title}}` to insert the page's title."
- "Default OG description" — text area, 110–160 char helper.
- "Default OG image" — uploader with the same 1200×630 dimension warning + one-click `sharp` resize as the per-page editor.
- Live preview at the top showing what the default share card looks like, rendered with `{{page_title}}` substituted as "Example Page Title."

### Seed Dandy

Pre-seed the Dandy tenant record with these defaults (this is the only tenant-specific data in this PR; all other tenants get `null` defaults and fall through):

- `default_og_title`: `"Meet Dandy | The Modern Operating System for Dentistry"` (54 chars — inside the optimal range)
- `default_og_description`: leave `null` for now (Dandy hasn't picked one; they can set it themselves in the tenant settings UI). The cascade will fall through to derived/system.
- `default_og_image_url`: upload Charlotte's provided Dandy brand OG card (1200×630, dark green background with "dandy" wordmark left, "Welcome to the future of dentistry" tagline right, faint tooth/jaw line-art) to the Dandy tenant asset bucket. Verify the URL is publicly accessible (not behind auth — social scrapers can't auth). Store the resulting CDN URL.

For the Dandy image upload: if the asset isn't yet in the tenant bucket, ask Charlotte for the source file or pull it from wherever Dandy's brand assets currently live (probably their existing brand-import or marketing site). It should be the 2400×1254-ish image she shared in this PR's context; resize to exactly 1200×630 via the same `sharp` center-crop pattern Part A uses.

## Step C.4 — Page-create defaults + page-publish emission

When a tenant creates a new page, pre-fill the **per-page** OG fields by running the resolver helper above and writing the resolved values back so the user sees them in the editor (rather than empty fields). Users can override; if they don't, the tenant default flows through naturally.

If the tenant page rendering layer isn't already reading `meta_title` / `meta_description` / `og_image` and emitting them into the page `<head>`, wire that up — using the resolver helper so the cascade applies. The marketing prerender uses `usePageMeta` for this; the tenant page rendering layer may use a different mechanism — find whatever the published-page rendering layer does and make sure all 3 resolved fields end up in the final HTML `<head>`.

## Don't

- Don't change the homepage title past 65 chars — Facebook truncates ~60 and Twitter ~70.
- Don't shorten descriptions past 110 chars — under 110 reads thin in the share preview.
- Don't replace the marketing OG image with a different design — scope is dimensions, not creative.
- Don't skip the marketing prerender step. The site serves static HTML to scrapers; without re-running the prerender the new tags won't land in production HTML.
- Don't touch the `usePageMeta` hook itself or the prerender script — they work; the data being passed in is what's wrong.
- Don't blanket-replace "revenue teams" with "one-team GTM" across the site. The Part B keep-list is intentional; deviating dilutes both phrases.
- Don't gate Part C on Parts A/B if you have to ship in phases — Part C is the bigger lift and shipping it later than the launch is fine. Parts A+B should ship before PH.
