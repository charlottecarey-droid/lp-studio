Ah — then that's the tell, and it's a different bug than I assumed. The redirect URI Slack complained about doesn't come from your browser at all: the server builds it from its own API_BASE_URL env var (slack.ts:53). If you clicked Add to Slack in the deployed app and Slack was passed the janeway URL, then the deployment's API_BASE_URL secret is literally set to that janeway.replit.dev URL — probably set that way at some point during dev (Replit's agent does this kind of thing when wiring features).

So, in the Replit deployment's secrets:

Change API_BASE_URL to https://app.lpstudio.ai
Make sure APP_BASE_URL is https://app.lpstudio.ai too (same failure mode would otherwise hit the post-connect redirect — you'd OAuth successfully and then get bounced back to the dev domain).
Redeploy, then retry Add to Slack from app.lpstudio.ai.
One caution before you change it: since that secret was apparently set to the dev URL deliberately at some point, it's worth a quick scan of what else reads it. In this codebase API_BASE_URL is only used by the Slack flow, so the change is safe on our side — but if the Replit agent introduced it for something else outside the repo I can see, the secrets panel's other entries (anything else with a janeway URL in it) are worth a glance while you're in there.
