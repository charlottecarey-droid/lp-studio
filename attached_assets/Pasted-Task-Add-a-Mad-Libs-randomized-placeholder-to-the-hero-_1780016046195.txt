Task: Add a Mad-Libs randomized placeholder to the hero textarea
The marketing hero at artifacts/lp-studio/src/marketing/components/AssembleScene.tsx has a textarea with a static placeholder ("A pricing page for a B2B platform aimed at COOs"). Replace that single placeholder with a randomized combination drawn from three arrays — picked once per page mount, kept stable during the visit.
Implementation:

Create artifacts/lp-studio/src/marketing/lib/madLibsPlaceholder.ts. Export the three arrays + a generatePlaceholder() function + a useMadLibsPlaceholder() React hook that runs the random pick once on mount.
Update AssembleScene.tsx to import and use the hook. The textarea's placeholder attribute reads from the hook.
First-paint fallback: during SSR/prerender, the random pick hasn't run yet — render a stable default ("Describe the landing page you want") for the initial paint, then swap to the random pick on client hydration. Avoids hydration mismatches.
Keep the existing "Or start from: Pricing page | Event landing | Product hero | Demo-request page" chips below the textarea. The chips are the structured menu; the placeholder is the unstructured inspiration. They complement each other.

The hook + function
tsimport { useEffect, useState } from "react";

function pick<T>(arr: T[]): T {
  return arr[Math.floor(Math.random() * arr.length)];
}

/**
 * Weighted subject picker — outlandish/personality subjects appear at most
 * ~10% of the time (1 in 10 placeholders). Keeps the page B2B-credible
 * while still surfacing personality regularly under auto-rotation.
 */
function pickSubject(): string {
  return Math.random() < 0.10
    ? pick(outlandishSubjects)
    : pick(seriousSubjects);
}

export function generatePlaceholder(): string {
  const template = pick(templates);
  const subject = pickSubject();
  const qualifier = pick(qualifiers);
  return template.replace("{subject}", subject) + qualifier;
}

/** Returns a stable random placeholder per page mount. Falls back to a
 *  default string on first paint to avoid SSR/prerender hydration mismatches. */
export function useMadLibsPlaceholder(): string {
  const [placeholder, setPlaceholder] = useState<string>(
    "Describe the landing page you want"
  );
  useEffect(() => {
    setPlaceholder(generatePlaceholder());
  }, []);
  return placeholder;
}

Cross-cutting requirements

Don't auto-submit the placeholder. If a user clicks Generate without typing anything, show a soft validation ("Type a brief to continue") — do NOT submit the placeholder string as the prompt. Placeholders are inspiration, not input.
Hydration: the useState initial value is the SSR-safe default ("Describe the landing page you want"). The random pick only runs on the client via useEffect. This prevents prerender + hydration mismatch warnings.
Accessibility: screen readers reading random placeholders is fine, but add an aria-label="Describe the landing page you want" to the textarea so the assistive-tech experience is consistent regardless of which placeholder rendered.
No tracking on the placeholder itself. We don't need to log which placeholder a user saw. If we later want to A/B test prompt sets, that's a follow-up.
